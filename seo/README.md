# The SEO content pipeline

Four stages, two human approval gates. Claude does the research, the writing and
the publishing; a person decides what gets written and what goes live.

```
  ┌── 1. IDEAS ────────┐   /seo-ideas
  │  DataForSEO research│   → writes Idea rows + briefs to Notion
  └──────────┬──────────┘
             │
  ┌── 2. APPROVE ──────┐   ** HUMAN **
  │  Idea → Approved    │   in Notion. Rejected = never propose again.
  └──────────┬──────────┘
             │
  ┌── 3. WRITE ────────┐   /seo-write
  │  post → repo branch │   → draft: true, Stage = Content review
  └──────────┬──────────┘
             │
  ┌── 4. APPROVE ──────┐   ** HUMAN **
  │  read the draft     │   Content review → approve
  └──────────┬──────────┘
             │
  ┌── 5. PUBLISH ──────┐   /seo-publish
  │  date + merge main  │   → site publishes itself on the date
  └─────────────────────┘

  /seo-report — measures it, monthly, and feeds stage 1.
```

**The board:** https://app.notion.com/p/7fab09d9d487475590ce483e8f2979a6

You only ever edit one field on it: **Stage**. Everything else is filled by the
pipeline.

## Running it

| | |
|---|---|
| Monday | `/seo-ideas` — 3 ideas for the week. Approve in Notion. |
| Monday–Tuesday | `/seo-write` — one session per post. |
| Wednesday | Read the drafts. Approve. `/seo-publish`. |
| Monthly | `/seo-report`. |

To run stage 1 unattended, `/schedule` it weekly. Stages 2 and 4 are
deliberately not automatable — they are the point.

## How scheduled publishing works

There is no publishing server. Two pieces do it:

- `isLive` in `src/lib/blog.ts` hides any post whose `published` date is in the
  future — from its route, the index, the sitemap and the feed.
- The daily cron in `.github/workflows/deploy.yml` (06:15 UTC) rebuilds.

So a post is **merged to `main` the day it is approved, dated the day it should
appear**, and the first build on or after that date publishes it. Nothing has to
run on the day.

One failure mode to know: **GitHub disables scheduled workflows after 60 days
with no commits to the repo**, silently, with one email to the repo owner. If
posts stop appearing, check that before checking anything else. `/seo-report`
sweeps for it.

## The files

| | |

## What the numbers said on day one

61 posts, 257 ranked keywords, ~147 visits/month, and **zero top-3 rankings**.
The bottleneck is not how much gets published — it is that almost nothing
published is competitive. `strategy.md` is the response to that, and it is why
the mix is 2 new + 1 refresh rather than 3 new.

The single most valuable thing on the board: `airtable consultants`, 210/mo,
$30 CPC, position 32 — answered by a blog post about hiring consultants while
the actual service page ranks for nothing.
